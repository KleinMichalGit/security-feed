Drupal patches critical RCE flaws, warns exploits may emerge soon

news BleepingComputer · 2026-10-17 · ↗ original

Drupal has patched two critical vulnerabilities that could allow attackers to execute code remotely on websites running any supported version of the content management system.

The security issues impact the software core's Field UI module and the contributed Entity List module. Drupal issued an advance warning at the beginning of the week, urging administrators to apply updates promptly because attackers could develop exploits shortly after the vulnerabilities’ disclosure.

“The Drupal Security Team urges you to reserve time for core updates at that time because exploits might be developed within hours or days,” the project's security team warned.

“We recommend updating to the latest supported patch (bugfix) release for your site's version of Drupal before October 14, so that you can address any other upgrade issues before the security window.”

Drupal is a free, open-source content management system used to build and manage websites, particularly popular among government agencies, universities, and non-profit organizations.

According to the project’s website, more than one million websites run on Drupal.

Earlier this week, the open-source project disclosed the two details, noting that "all currently supported versions of Drupal core are affected."

  • CVE-2026-108097: A remote code execution vulnerability in Drupal core’s Field UI module that could allow attackers to execute arbitrary code on affected servers.
  • CVE-2026-108099: A flaw in Entity List, a contributed module for creating entity lists without Views, that could enable remote code execution.

The security advisory for CVE-2026-108097 notes that the flaw cannot be exploited using Drupal core alone, but contributed modules can provide multiple exploitation paths, including at least one that requires no authentication.

Additionally, custom code may also expose the vulnerable functionality.

Successful exploitation of CVE-2026-108099 requires a similar interaction with contributed modules or custom code and includes at least one known exploitation path that does not require authentication.

Administrators are urged to update Drupal core to version 10.6.19, 11.3.19, or 11.4.10, depending on their release branch, and update Entity List to 3.0.10.

"All versions of Drupal prior to 10.6.x, as well as all versions of Drupal 11 prior to 11.3.x, are end-of-life and no longer supported," the developer said

The flaws also impact Drupal 12 pre-releases before beta2, but these are not meant to be used in production environments. The final stable 12.0 version will include fixes for both flaws.

Administrators who cannot upgrade to a secure version are advised to uninstall Drupal’s core Field UI module (field_ui) as an effective mitigation measure.

Also, Drupal Steward protects against some known attack vectors but does not cover every possible exploit.

Cybercrims go beyond stealing data to attack physical building systems

news The Register · 2026-10-17 · ↗ original

Late Sunday night, a still-unknown cybercriminal or group hacked thousands of remote-controlled refrigeration systems across hundreds of French grocery stores, spiking temperatures, spoiling food, and sparking fires. This is part of an ongoing trend of attacking physical systems that can do damage in the real world. In August, a ransomware attack disrupted building-management systems at a Canadian hospital, affecting door access controls, central HVAC monitoring, and the issuing of staff access cards. And three years ago, cyberattacks hit Las Vegas casinos, causing slot machines to go dark, preventing payment kiosks and ATMs from spitting out cash, and locking guests out of their rooms when the electronic keys stopped working. Not all digital intrusions remain in cyberspace, and attackers don’t need to encrypt files and steal data to cause chaos. Hitting physical systems often produces more severe consequences - and turns up the heat on executives to pay an extortion demand. “There was one gig where the customer was refusing to pay, and so the threat actor was like, ‘Hold my beer, have fun getting into your offices,’ and locked everybody out,” Tim Beasley, a senior incident response consultant at Semperis, told The Register. Beasley won’t name the customer, or provide any incriminating information, but said the incident response involved police smashing glass in addition to his team recovering compromised data. “The cops had to break in, and literally get into the building, breaking some windows, so the customer was able to finally get back in,” he said. We asked if the customer paid the ransom demand, and Beasley yelled: “Oh, hell, no!” A report published earlier this month by ServiceNow’s Armis Labs found increasing evidence of ransomware attackers using physical consequences as leverage in their intrusions. “Today’s BAS operate at the intersection of IT and OT worlds, creating unprecedented exposure,” the report said. Ransomware with physical consequences Building automation systems - BAS - are the critical systems that control and monitor facilities’ HVAC, lighting, energy usage, and water consumption. They also oversee badge readers, door locks, surveillance cameras, fire alarm control panels, and other physical safety equipment. As such, BAS make very attractive targets for ransomware operators looking for high-pressure ways to extort organizations into paying multi-million ransom demands. These systems also appeal to government-backed goons and hacktivists looking to ensure maximum psychological and physical impact during destructive cyberattacks. Armis Labs found 73 percent of organizations own BAS that have been used in ransomware attacks, and this same percentage have known exploited vulnerabilities in at least one of their building automation systems. Additionally, 91 percent of BAS communicate over insecure protocols - opening up an even bigger attack surface for cyber-miscreants wanting to cause physical harm. “The primary thing that we see with any attack on building management systems or physical systems: It’s a great place for the threat actor to hide,” Michael Freeman, ServiceNow’s senior director of threat research, told The Register. “It's easier for them to compromise, and it's easier for them to hide in.” BAS and operational technology (OT) in general have fewer security controls than IT systems. Most require continual uptime, which makes them harder to patch or even scan for vulnerabilities and misconfigurations as this may lead to outages. “One case in particular, against a very large financial institution, the threat actors were staying low and quiet by attacking their BMS systems, and then pivoting into the IT environment,” Freeman said. The intruders were routinely caught - and booted from - the financial institution’s IT systems, so they built backdoors into the BMS to ensure persistent access to both OT and IT networks. “We're also seeing threat actors using AI to understand more building automation systems, especially ones that are using obscure OSs like VxWorks, older Unix-type systems,” Freeman said. AI has entered the chat As multiple security experts have told us in previous interviews, security through obscurity is dead. Not only does AI make it easier for attackers to find bugs – some very obscure and decades old - but it also means criminals no longer need to be OT experts to carry out destructive cyberattacks on critical networks and facilities. Instead, they can use AI to learn all about the obscure protocols and proprietary hardware and software that historically made industrial control systems black boxes. “It’s easier to understand what the controls are,” Freeman said, using the example of an attacker trying to take down a plane, or some similar catastrophic cyberattack. Historically, even advanced, government-backed hacking squads would “be quiet, because you don't know what changing certain settings is going to do,” Freeman explained. “Now you can use AI to say, ‘If I compromise a weight and balance system for airlines, all I need to do now is move this number here to this number, and I just told the system to load heavy stuff on the right side of the plane instead of equal distribution.'” Freeman told us he has seen attackers break into airlines’ OT gear in the past. “But they didn’t know what they were getting into, and so they left them alone,” he said. “Those do cause me concern because in the past I've helped to kick people out of those types of systems.” Industrial orgs increasingly under attack OT security provider Dragos tracks ransomware groups’ claims against industrial organizations on the criminals’ leak sites, along with publicly disclosed intrusions affecting manufacturing and other critical sectors. To be clear: claims on leak sites aren’t always accurate or even true, and the claim itself doesn’t mean operations or control systems were hit. Since 2022, however, “the numbers have been consistently increasing,” Lexie Mooney, senior threat analyst at Dragos, told The Register. The cybersecurity firm tracked 995 ransomware attacks against industrial orgs in 2023, a 49.5 percent increase from 2022. That number jumped more than 87 percent in 2024. Active ransomware groups targeting industrial orgs also grew in 2024 to 80 groups, up from 50 the year before. Dragos tracked 119 ransomware groups impacting more than 3,300 industrial organizations in 2025, and the incidents have steadily increased every quarter this year: 1,020 incidents in the first quarter of 2026 and 1,140 incidents in Q2. “The vast majority of cases are opportunistic,” Abdul Alamri, a senior threat analyst at Dragos, told us. “In some of the cases that we have seen an operational impact, either physical systems or an OT operation, it’s just the nature of the opportunism on the part of those ransomware groups.” This is partially due to the complexity of OT systems, he added. “Ransomware groups want to disrupt operations, and put pressure on the victims to pay the ransom,” Alamri said. “They don’t want to invest that time and effort to target complex systems." It’s usually quicker and easier for financially motivated crims to affect operations via IT systems - as the extortionists did in the August 2025 Jaguar Land Rover (JLR) breach, which halted manufacturing and crippled business operations for months. Internet-connected OT: the next 'low-hanging fruit' The other side of this complexity, however, is that many organizations themselves still lack visibility into their OT environments. Dragos estimates that fewer than 10 percent of OT networks worldwide currently have sufficient network monitoring in place. Plus, in 30 percent of incidents the security firm responded to in 2025, the investigations did not begin with a detection alert, but with someone noticing that “something seemed wrong” in operations. This lack of visibility, combined with threats from AI, worries Alamri. “If you compare the risk that we have seen from humans, to what we are about to face in the near future with AI agents who might continuously try to break into those systems - it’s a pretty dark future if we don't take the right measures to protect ourselves against it.” As organizations get better at patching and securing IT systems, attackers will likely look to internet-connected OT systems where digital compromises have real-world consequences, according to Matt Hayden, VP of cyber and emerging threats at General Dynamics Information Technology. “We all anticipate that as we get better at reducing the IT low-hanging fruit, OT will become a vector of much more scrutiny and much more attention,” Hayden told The Register. Before joining GDIT, Hayden served as the assistant secretary for cyber, infrastructure, risk and resilience policy at the US Department of Homeland Security. Compliance vs. security “There is a big focus on the hardware being connected for the purpose of compliance - and to make sure that, in the name of compliance, we aren't opening back doors, to devices that traditionally wouldn't have to be connected to facilitate their service,” he said, using refrigeration units as an example of one such system that is now internet-connected for compliance purposes. This was prior to the French supermarket hacks. Refrigeration units’ monitoring systems connect to the internet so their owners and operators can prove to regulators that the units maintain their uptime and temperature in accordance with regulations. “So if the health department comes by, they say, ‘Look, my refrigerator was at 27 degrees for the last 72 days,' and they have a check mark, and they get their A plus. But that simple connectivity is also a vector in which that particular refrigerant unit could be targeted for disruption,” Hayden said. About a week after our interview, criminals did exactly that. “The recently reported exploitations of commercial refrigeration units represent a significant example of devices without digital value, no sensitive data or extended enterprise access, being exploited by being connected to the internet with unpatched firmware,” Hayden told us in a subsequent email. He said he expects the attribution to be “less nation-state, and more likely those looking for targets of opportunity to identify what could be done with the unpatched systems.” “The consequences are food supply degradation at a small scale, but it is an important example of what could happen at scale very quickly with more consequential operating equipment,” Hayden said.®

MALFEX npm Package 'imgdecode' Hides Shellcode Loader in Windows Native Addon

news The Hacker News · 2026-10-17 · ↗ original

Cybersecurity researchers have discovered a malicious npm package that's part of a recently disclosed software supply chain attack campaign dubbed MALFEX.

The package, named "imgdecode," was uploaded to the package registry on September 30, 2026, by a user named "malfexteste8." It has been downloaded 979 times as of writing and is still available on npm as of writing. The latest version of the package is 1.0.3.

"The npm package imgdecode hides a malicious loader in a compiled Node.js addon," SafeDep said. "Its nine-line JavaScript file loads a Windows dynamic-link library (DLL). When a Node.js program calls require('imgdecode') from a Windows console, the DLL attempts to download encrypted shellcode from GitHub. It decrypts the response and injects the result into a new dllhost.exe process."

First documented by both Checkmarx and CloudSEK, MALFEX is the name assigned to a long-running campaign in which an unknown threat actor has been publishing malicious packages to npm since August 6, 2023, with an aim to compromise Windows systems. These packages were published across five npm publisher handles: malfexkkj, malfex_user, malfexteste2, malfexteste3, malfexteste4.

Of the eight identified packages, three were found to act as a loader for Overlord RAT, while three others ("cdn-img-fetch," "img-to-native," and "native-runner") worked together to download and run a Node.js stealer. A third infection pathway involved the use of a postinstall hook to execute JavaScript capable of contacting an external server and retrieving an unspecified next-stage binary.

Interestingly, the threat actor behind the campaign appears to be responding to public disclosures and npm removals by publishing replacements for "native-runner" and "img-to-native" within two days in the form of "runhelper" and "imgbundle." That same day, the first version of "imgdecode" was published. The timeline of events is as follows -

  • September 26, 2026 - cdn-img-fetch, img-to-native, and native-runner 1.0.0 published
  • September 28, 2026, at 4:06 p.m. UTC - npm removes native-runner and img-to-native
  • September 30, 2026, at 3:29 a.m. UTC - imgbundle 1.0.0 published, replacing img-to-native
  • September 30, 2026, at 3:37 a.m. UTC - runhelper 1.0.0 published, replacing native-runner
  • September 30, 2026, at 4:13 p.m. UTC - runhelper unpublished
  • September 30, 2026, at 10:32 p.m. UTC - imgdecode 1.0.0 published
  • September 30, 2026, at 11:07 p.m. UTC - imgdecode 1.0.1 published
  • October 1, 2026, at 5:48 p.m. UTC - imgdecode 1.0.2 published
  • October 7, 2026, at 11:06 p.m. UTC - npm removes imgbundle
  • October 8, 2026, at 1:03 p.m. UTC - npm removes cdn-img-fetch
  • October 11, 2026, at 10:09 p.m. UTC - imgdecode 1.0.3 published

The Node.js stealer chain is notable for the fact that none of the packages featured an install hook. Instead, the malicious code runs when "native-runner" is loaded. The package lists "img-to-native" as its dependency, which, in turn, has "img-to-native" as a dependency.

The exact functionality of each of these packages is below -

  • cdn-img-fetch downloads "banner.png" from a GitHub repository ("cavecrew/proj") and extracts an encrypted blob.
  • img-to-native decrypts the blob using the key "malfexteam2027" and writes the contents to disk as a Go executable ("%APPDATA%\Microsoft\Windows\node_runtime_helper.exe").
  • native-runner executes the Go executable, which then downloads the stealer binary ("setup.exe" aka movinlike) from "104.234.65[.]75:700."

"Runhelper," advertised as a helper utility for "launching native binaries from Node.js projects," functions similarly to "native-runner" in that it's designed to run malicious code. Its primary responsibility is to locate a JPG file ("cdn-img-fetch/.runtime/rt.jpg"), extract shellcode from it, copy it into executable memory, and run it using Koffi, a Foreign Function Interface (FFI) module for Node.js.

"Six hours after runhelper was unpublished, the operator published imgdecode with a compiled DLL to run the shellcode," SafeDep said. "From version 1.0.1, the DLL also downloads and decrypts the payload. Versions 1.0.1 and 1.0.2 still call require('imgbundle') before loading the DLL. Version 1.0.3 removes that dependency and needs no other MALFEX package."

Like in the case of "runhelper," version 1.0.0 of "imgdecode" waits for "imgbundle" to write a file at the location "cdn-img-fetch/.runtime/" and, once it becomes available, reads its contents into memory, and passes them to a native Node.js addon for decoding the data.

The addon is a 64-bit Microsoft Visual C++ (MSVC) DLL that first checks if it's running in a developer's terminal, and then proceeds to fetch a JPG file ("banner.jpg") from the same repository ("cavecrew/proj"), decrypt the embedded payload using the key "nif-runtime-2027," and ultimately inject the output into "dllhost.exe."

"After decryption, the DLL checks the first bytes of the plaintext," SafeDep explained. "If they match a JPEG or PNG signature, the DLL stops. Inference: the operator could turn the loader off by serving encrypted content that decrypts to an image. Serving an ordinary image would instead generally cause decryption to fail before this check."

Although the GitHub account "cavecrew" is no longer accessible, an Internet Archive screenshot of the image file dated October 6, 2026, shows that it contains the same Go-based downloader used for retrieving the Node.js stealer and remote access tool ("movinlike") from "104.234.65[.]75:700."

The Node.js application includes a .env file containing a command-and-control (C2) address ("104.234.65[.]75:7007") and a MALFEX license key, indicating the use of a malware builder or licensing system to craft such payloads.

The malware runs anti-analysis checks that audit for the presence of virtual machines, sandboxes, and analysis tools like Process Monitor and Wireshark, before harvesting files matching seed phrases and specific extensions (.kdbx, .pem, .ppk, and .env), as well as data from Chromium-based web browsers, Discord, Telegram, cryptocurrency wallets, and gaming apps (Steam, Epic Games, Riot, Battle.net, Minecraft, and Ubisoft).

It can also establish a WebSocket connection to the C2 server, allowing it to accept commands for shell execution, file transfer, process control, clipboard access, screenshots, and mouse and keyboard input. For persistence, it adds a Registry Run key and creates a scheduled task named "MicrosoftEdgeUpdateService."

Developers who have installed any of the aforementioned packages should treat their Windows systems as potentially compromised, isolate them, check for persistence entries, rotate credentials, and transfer funds to new wallets if seed phrases were stored in them.

Israeli Ad Firm Doubled as Candiru’s Zero-Click Spyware Delivery Channel

news SecurityWeek · 2026-10-17 · ↗ original

Candiru spyware has infected devices at international news network Al Jazeera in zero-click attacks, via targeted advertisements, Canadian internet watchdog group Citizen Lab reports.

As part of the operation, dubbed AdFection, ads purchased by Israeli company Discover-Tech were used to de-anonymize, fingerprint, and infect users, and also allow threat actors to track millions of devices.

As part of the online advertising ecosystem, companies bid at billions of daily Real-Time Bidding (RTB) auctions hosted on ad exchanges for a chance to serve an ad to a user.

Ad exchanges collect extensive device and user data that enables tracking, and ads may contain code that runs in the user’s application or browser, typically for tracking users, impressions, and clicks.

However, ads may also contain malicious code potentially leading to malware infections and, courtesy of the various identifiers used within the ecosystem, could be used to target specific individuals with spyware, Citizen Lab says.

Discover-Tech, a seemingly legitimate advertising company, is likely the front for a large campaign involving spyware infection and espionage, serving as a bridge between ad vendors and mercenary spyware vendors.

Its Controlium platform enables the de-anonymization of millions of users, device fingerprinting, and zero-click hacking when an ad is displayed on the victim’s device.

While the company appears to work with multiple mercenary partners, Citizen Lab has confirmed its use to profile users and infect them on behalf of Candiru, an Israel-based spyware vendor.

Many of Discover-Tech’s ads contain a script that automatically connects to its infrastructure, submits an advertising ID for the user, and executes JavaScript code served based on a combination of IP addresses and identifiers.

Between 2024 and 2025, at least 45 devices within Al Jazeera were targeted in AdFection attacks leading to Candiru’s spyware.

Citizen Lab says it identified a Discover-Tech server that exposed four billion ad bid records, revealing that Discover-Tech’s ads appeared across nearly 200,000 unique websites and Android and iOS applications worldwide.

“Given the current threat posed by Discover-Tech’s AdFection vectors, and the evidence of wide-scale targeting, we judge that the most feasible protection is for defenders to block targeted ads at the gateway. This defensive recommendation holds until the industry has shown that it is reliably able to block all AdFection-style vectors,” Citizen Lab notes.

Inbox flooded with sign-up messages? Email bombing explained

threat-intel ESET WeLiveSecurity · 2026-10-16 · ↗ original

In September, reports emerged that a Virginia woman had been submerged by a flood of emails. Hundreds of automated messages poured in over a 24-hour period, including newsletters and promotions she’d never signed up to. But this was no ordinary spam campaign. The real reason behind the inbox blitz was to bury a legitimate email from the victim’s bank warning her about a fraudulent laptop purchase.

This is email bombing. And if it’s happened to you, it could be a warning sign that your identity or online accounts have been hijacked by fraudsters.

What is email bombing?

Sometimes called “form bombing,” “list bombing” or “subscription bombing,” email bombing attacks usually follow the same pattern. First, an attacker gets hold of your email address. They could do this from historic data breaches, marketing databases, online leaks, or even a prior phishing attack. Once they have it, they’ll use automated, bot-powered tools to sign up for hundreds or thousands of legitimate online services like newsletters, subscriptions, mailing lists, free trials, and competitions.

These will each generate a welcome email or similar. And because they are usually legitimate services, they’re often not blocked by spam filters. The result is an inbox overflowing with messages.

Why do they do it? Two reasons are behind most email bombing attempts:

  1. The scammer is trying to distract the victim so that they don’t see a genuine email among all of the artificially generated ones. They may have hijacked one of your accounts and reset the password, triggering a notification to your inbox. Or they may have made a fraudulent purchase in your name, with the invoice subsequently emailed to you. The main point is to create a smokescreen which prevents you from tackling the more serious fraud.
  2. The hacker may subsequently contact you pretending to be a tech support engineer. They’ll claim to be able to solve your email ‘problem’ and either request a fee to do so, or trick you into installing remote access software so they can take a look at your machine. That could enable them to steal sensitive information on your computer like passwords stored in the browser. Or even install additional malware.

In a corporate scenario, the bomber is most likely trying to distract the cybersecurity team from a more serious attack, such as a data breach or a business email compromise or invoice fraud attempt. Alternatively, they may be trying to disrupt operations as leverage for extortion – ransomware affiliates have used email bombing as a precursor to a fake IT help desk contact in order to get remote access. Or it could even be a disgruntled employee or former worker.

I’ve been email bombed: what next?

If you’ve logged on to find your inbox overwhelmed, don’t panic. Rather than try to unsubscribe to all of the random services you’ve been signed up to, focus your energy on finding the threat that your attacker wanted to hide. Search for security alerts, new device sign-ins, email/phone number changes, password changes/resets, or purchases. Look through your spam folder as well as your inbox, in case the message has ended up there.

If you don’t immediately see anything out of the blue, check your most sensitive accounts individually. These could include

  • Bank/PayPal/credit card/crypto
  • Apple/Google/Microsoft
  • Social media accounts

Look for any suspicious activity: new devices or payment methods added, passwords that may have been changed, and/or recovery details altered. It’s also worth checking your email forwarding rules and sent/deleted items folders for anything unusual.

If you notice something unusual, try to lock the hacker out by changing the password to a unique, strong credential, and enable two-factor authentication (2FA) for extra login security. Ensure the correct recovery email address/phone number is listed (or they may be able to reset the account again). Contact the company itself if you’re concerned about fraud.

Remember to preserve anything related to a possible account takeover or fraud attempt. Only purge when you’re confident it’s over. You can do this more quickly by trying to identify patterns in the messages (e.g., senders, date ranges, domains, etc.). Then you can bulk select and delete in batches.

It goes without saying that you should put the phone down immediately if anyone calls you claiming to be a tech expert who can sort out your email problem.

How to prevent email bombing

Of course, prevention is usually better than cure. And while it’s not always possible to stop your email ending up in the wrong hands, you can limit the damage by ensuring that it’s not exposed on public-facing web pages like social media profiles. Also follow security best practices to stay safe from phishing attacks.

Next, keep your most sensitive accounts as secure as possible. This includes your primary email address, which will be used to receive password reset messages from other online accounts. Use a password manager to ensure they all have strong, unique credentials. And 2FA for an extra layer of security (e.g., via an authenticator app or passkey).

It may also be worth using a secondary email address for less important correspondence like shopping, travel and other leisure activities. This way, if this account is hit by an email bomb, at least your most important messages (bank, government, healthcare etc) are safe.

There’s no silver bullet to prevent email bombing. But account security best practices will help to reduce the chances of an explosion of messages in your inbox.

Frequently asked questions (FAQs)

Why is my inbox full of hundreds of sign-up emails?

You may be the victim of an email bomb (aka form bomb/list bomb/subscription bomb). A fraudster has used automated tools to sign your email address up to new services for one of two reasons. Either they’re hoping to bury a legitimate security or anti-fraud message, or they’re going to call you pretending to be a tech support engineer that can help.

Has my email account been hacked if it’s full of sign-up emails?

Probably not. Fraudsters may have scraped it off the public web, harvested it from a historic data breach, or even bought it from a marketing database. However, the security/fraud ‘event’ they’re trying to hide with the email bomb tactic may have involved account takeover.

My inbox is full of new messages; what should I do?

First, search for the notification they’re trying to hide in the spam and preserve it. Search for security alerts, new device sign-ins, email/phone number changes, password changes/resets, or purchases. Look through your spam folder as well as your inbox. If you don’t find the message, check your sensitive accounts (bank, social media, tech etc) for unusual activity. Change passwords to a unique, strong credential, and add enable two-factor authentication (2FA) for extra log-in security.

I’ve been email bombed. Should I unsubscribe to all of the new emails?

No, it’s important to find the security notification or fraud warning the attacker is trying to hide, and preserve it. Only purge once you’re confident the issue has been resolved. Consider speeding up the process by deleting in batches (search for common senders, date ranges, domains etc.).

What if someone contacts me to fix the problem?

They’re a fraudster who wants to charge you a fee or trick you into installing remote access software on your machine, which could lead to malware or data theft. Put the phone down on them.

By chaining the vulnerabilities together, attackers were observed writing webshells into the application filesystem, allowing them to execute commands as SYSTEM and root. On 12 October 2026, Ahsay released hotfixes for the issues.

Even though we had not heard of this specific backup solution before, given the in-the-wild exploitation reports, we dug in.

Unpacking the Installer

AhsayCBS is available to install on both Linux and Windows servers. This analysis focuses on the Linux installer which is released as a tarball, cbs-nix-tar.gz. Inside the tarball, you’ll find that it’s a Java application, shipped with its own JRE, and built upon the tomcat framework.  

The interesting surface lives in the web applications under webapps/. Alongside the main console (cbs) and the client-facing backup service (obs) sits rps, the Replication Receiver. Taking a look at its struts-config.xml, a familiar pattern emerges – a set of .do actions under /rps/api/json/, each mapped to a Java class:

Figure 1. API routes exposed in webapps/rps/WEB-INF/struts-config.xml.

Every one of these JSON actions extends a common base class, com.ahsay.obs.api.json.JSONApi. That base class is where authentication is supposed to happen, and it is where we first look.

CVE-2026-105133: The Path to Unauthenticated API Access

The first vulnerability can be found in the JSONApi base class. JSONApi.execute() runs before any action-specific logic. Reading the source, the authentication decision comes down to three booleans:

Figure 2. The only credential gate in JSONApi.execute()

b is true only when the caller already holds an authenticated session. equals2 is the FromObc flag, honored only for actions that opt in. And equals is the FromServlet flag, read straight out of the attacker-controlled JSON request body. checkSysPwd() is the one function that validates the system administrator’s username and password, and it is called only when all three booleans are false.

Which means a request that simply includes "FromServlet":"Y" sets equals to true, and the credential check is never reached. The resolved administrator object is computed a few lines later but its value is never checked, and the downstream actions never reference it.

Confirming the bypass takes two requests. Without the flag, the server demands credentials:

The Path to Admin

With the entire API now unauthenticated, one of the most impactful actions an attacker may take is to add a new administrative user. Among the obs actions is com.ahsay.obs.api.json.system.systemUser.AddSysUser, the endpoint the console uses to create system administrators.

Reading its doAction, the handler pulls LoginName, Password, and Role out of the request, validates the role against the Admin.Type enum, and builds a new administrator:

Notably, AddSysUser never consults the authenticated caller. Combined with the bypass, that is all an unauthenticated attacker needs to mint themselves an administrator:

CVE-2026-105134: The Path to Code Execution

The second vulnerability targets the Replication Receiver directly, and it is the one that lands a webshell. Replication in AhsayCBS mirrors a primary server’s data to a secondary “receiver.” The receiver is configured through UpdateReceivers, and it ingests replicated files through a service, com.ahsay.ars.obs7.FileService, exposed at /rps/obs7/rpsfile.

Starting from the configuration side, an auth-bypassed call to UpdateReceivers.do with Id=0 creates a new V7 receiver. The attacker controls its login, its password, and its SystemHome. SystemHome is run through a system-folder denylist (com.ahsay.c) that blocks the obvious targets like webapps, conf, tomcat, and the rest, so we point it somewhere benign like /opt/AhsayCBS/rpsrecv_x and move on.

The write happens later, when we feed the receiver a file. FileService authenticates the upload by matching the receiver’s login and password – both of which we just set – carried in a set of base64-encoded X-RSW-Request-* headers. It then builds the destination directory from two more attacker-controlled headers, UserHome and TopDir:

Figure 6. getReplicatedPath concatenating an attacker string onto the write root

FileList.a() escapes exactly two characters, % and :. It leaves ../ untouched. And unlike SystemHome at creation time, this computed path is never run back through the com.ahsay.c denylist. The call chain that matters is doUpload -> FileService.a() -> getReplicatedPath(), and the denylist appears in none of it.

Which means a UserHome of ../../webapps/rps walks the write directory straight out of the receiver’s home and into a live, web-served Tomcat application:

C:\AhsayCBS\rpsrecv_x\files\..\..\webapps\rps   ->   C:\AhsayCBS\webapps\rps

Figure 7. The traversal resolving into the web root

From there it is a single PUT of a .jsp file. The upload is a plain octet-stream body with the path and the receiver’s credentials in headers:

Figure 8. Writing the webshell into webapps/rps

Requesting /rps/status.jsp runs it. On a Windows receiver, the AhsayCBS service runs as LocalSystem, so the webshell executes as SYSTEM. On Linux it runs as root. The same cbs.jar drives both platforms; the only thing the exploit changes between them is the install root, because the receiver’s path validator happily accepts a C:\... absolute path and the server rewrites our forward slashes to backslashes on the way to disk.

Indicators of Compromise

  • Suspicious child processes spawning from **cbssvcX64.exe** (Windows) or the CBS JVM (Linux) – command interpreters, curl/certutil, miners, or persistence tooling.
  • New .jsp files under webapps/rps, webapps/cbs, or any served application directory, especially files that answer with a 404 unless a specific parameter is supplied.
  • New replication **receivers** whose SystemHome sits under the install directory, created outside a change window (System Logs → “Created new receiver”).
  • Unexpected **system administrator** accounts (ListSystemUsers), and API logon entries recording “Logon to API from IP address …” for accounts you did not provision.
  • Requests to /*/api/json/*.do and /rps/obs7/rpsfile/upload carrying a FromServlet field or X-RSW-Request-* headers from untrusted sources.

October 2026 Microsoft Patch Tuesday

threat-intel SANS ISC · 2026-10-13 · ↗ original

Microsoft today released patches for 1,417 vulnerabilities. 76 of these vulnerabilities are rated critical, with 7 critical vulnerabiilties requiring no customer actions. One vulnerability was disclosed before today's patch Tuesday, and one is already exploited.

CVE-2026-96951: An already exploited Windows Shell Security Feature Bypass Vulnerability. This vulnerabliity allows bypassing the "Mark of the Web" making it easier to exeucte code by sending a malicious message to a user via e-mail or instant messaging. The victim will still have to open the file.

CVE-2026-108398: This vulnerability, a .NET framework security feature bypass, could be used to bypass application control and execute unauthorized applications. Details were available public head of today's release, but Microsoft did not detect exploitation in the wild.

Windows DHCP Server: 10 remote code execution vulenrabilities, including five critical vulnerabilities, affect the Windows DHCP server.

CVE-2026-70571: Microsoft Exchange Server Remote Code Execution Vulnerability. Microsoft considers the attack complexity high. The vulnerability is triggered by an attacker sending a specific email to the exchange server that triggers the vulnerability during content conversion. 

Aside from these specific vulnerabilities, the larger number of Office vulnerabilities is noteworthy, and the Office updates should likely be addressed quickly.
