Microsoft fixes classic Outlook bug that hid Copilot buttons

news BleepingComputer · 2026-10-19 · ↗ original

Microsoft has fixed a known issue that removed the Copilot Chat and Copilot buttons in the classic Outlook desktop mail client for some Windows users.

As explained in an updated support document, affected users with the Copilot Chat (Basic) license or a Microsoft 365 Copilot (Premium) account no longer saw Copilot buttons in the side navigation and above the ribbon.

Those impacted by this experienced one or more of the following issues:

  • The Copilot button missing from the top-right area above the ribbon.
  • The Copilot icon missing from the left app bar or More Apps area in classic Outlook.
  • In Add Apps, Copilot may appear as an available app, but selecting Open does nothing.
  • Adding Copilot through ribbon customization may show the command as unavailable or grayed out.
  • Copilot remains available from other entry points, such as Outlook on the web or the Microsoft Copilot standalone app or web experience.

Microsoft first announced in June that it had fixed the bug with a service change, but last month it said it had started investigating again after recent updates caused it to resurface.

Now, Microsoft says it has finally resolved this classic Outlook issue, blaming it on a bug that prevented Outlook from retrieving some account information from the user's Outlook profile.

"We fixed an issue in classic Outlook that could cause the Copilot entry point to be missing from the navigation pane when required account information could not be retrieved from the user’s Outlook profile. The Copilot button might be missing for several different reasons, including licensing, Microsoft 365 app configuration, update channel, privacy settings, or other environmental factors," an update to the original support document reads.

"Because the missing button is a symptom that can have multiple underlying causes, we recommend following the guidance in Copilot troubleshooters and How to find and enable missing Copilot button in Microsoft 365 apps to identify and resolve the issue."

Microsoft also shared a temporary workaround for those still affected by this known issue, which requires enabling the "Show Apps in Outlook" option in classic Outlook settings by selecting the File tab, then going to Options > Advanced and checking the "Show Apps in Outlook" box under "Outlook panes."

Affected users can also use the new Outlook email client or Outlook Web Access (OWA), which are not affected by this bug, or create a new Outlook profile.

Since the start of the year, Microsoft has also resolved known issues that prevented some classic Outlook users from sending emails via Outlook.com and rendered the classic Outlook client unusable when enabling the Microsoft Teams Meeting Add-in.

Plex2Shell Exploit Chain Weaponized Against Plex Servers Hours After Disclosure

news SecurityWeek · 2026-10-19 · ↗ original

Threat actors began targeting Plex2Shell, a chain of four Plex Media Server vulnerabilities, one day after technical details and a working exploit went public.

The researcher who found the Plex2Shell bugs released a write-up and proof-of-concept (PoC) code on October 16. Tracked as CVE-2026-96652, CVE-2026-96654, CVE-2026-96655 and CVE-2026-96656, the flaws can be combined to run arbitrary code on an exposed server without valid credentials. The code runs with the same privileges as the Plex service.

The issues were reported to Plex on July 27, and the company confirmed them and awarded a bug bounty on August 4. On September 1, Plex announced it had already shipped fixes and asked server owners to upgrade.

A different researcher caught the attacks by setting up an internet-facing Plex honeypot running a vulnerable release. Before October 17, the decoy had drawn largely reconnaissance scans and generic attack attempts.

“As of this morning (Oct 17th), I finally saw in the wild exploitation,” the researcher wrote. The attackers used the publicly released exploit, the researcher said, though they may have tweaked the code.

The attackers were observed dropping a cryptocurrency miner built on XMRig. Later that day, a second program called myawesomeproxy also appeared on the honeypot. The researcher identified it as proxy software, and it shows a notice saying that anyone running it agrees to the potential use of their internet traffic.

Hackers steal customer data from major Russian hosting provider FirstVDS

news The Record · 2026-10-19 · ↗ original

Hackers have stolen passwords, access credentials and other sensitive data belonging to customers of Russian hosting provider FirstVDS after exploiting a vulnerability in software used to manage its servers, the company said over the weekend.

The attack, discovered on Saturday, affected part of FirstVDS's infrastructure, allowing the hackers to access data stored on customers' virtual servers without disrupting their operations. 

According to the company, the attackers exploited a vulnerability in VMmanager 6, a virtualization management platform developed by Russian software company ISPsystem. The platform allows hosting providers to manage virtual machines across multiple physical servers.

The hackers then deployed malware that allowed them to copy data from customers' virtual servers, including passwords, cloud service credentials, configuration files, cryptocurrency wallets and other files. The stolen information was transferred to a server controlled by the attackers, according to FirstVDS.

The company said the breach affected only some of its infrastructure but did not disclose how many customers or servers were compromised.

FirstVDS, which has operated since 2002, is one of Russia's oldest hosting providers. It rents virtual private servers that customers use to run websites, applications, databases and other online services. The company also offers servers hosted outside Russia, including in the Netherlands and Kazakhstan.

According to FirstVDS, the attackers were able to access customer data without directly compromising the virtual machines themselves. Instead, the malware mounted their disks in read-only mode, allowing it to copy information without modifying files or disrupting normal operations.

“As a result, there are no traces of the attack on the affected virtual servers, which continue to operate normally,” the company said.

FirstVDS warned customers who received breach notifications to assume that data stored on their servers had been stolen and urged them to change passwords and access credentials.

The company said it had disabled external access to the vulnerable management system and blocked communications with the attackers' server.

ISPsystem has released several patches since the breach, including an update deployed overnight on Monday, but the vulnerability has not yet been fully fixed, according to FirstVDS.

The software vendor has advised against restoring access to the management interface until additional security updates are available.

As of Monday, FirstVDS was still operating with some restrictions, including limited availability of VMmanager functions, according to its service status page.

The company has not disclosed how the attackers initially exploited the vulnerability, which versions of the software were affected or whether the stolen data has been used in further attacks. The identity and motives of the hackers remain unknown.

Training AIs to Solve CAPTCHAs

news Schneier on Security · 2026-10-19 · ↗ original

Interesting research:

Abstract: Vision-language models (VLMs) can solve visual CAPTCHAs without task-specific training, but the agents built on them approach every challenge from scratch. For such an agent, the hundredth instance of a familiar puzzle costs as much time and compute as the first. Specialized detectors invert the trade-off, answering in milliseconds but only for categories they were trained on. Neither improves with exposure. We study what changes when a solver improves with use. Our system pairs a fine-tuned YOLOv8 detector with an open-weight VLM behind a confidence-based router, and runs entirely from screenshots and operating-system input events, with no browser automation or DOM access. It reaches 85.4% overall and 84.2% macro accuracy across 16 classes, exceeding either component alone. Every answer VLM produces also serves as a training label, so the detector absorbs categories it was never trained for, typically after one or two encounters and without human annotation. The same loop also repairs it. A CAPTCHA operator can perturb images against the publicly released detector and drive its accuracy to 0%, but the perturbations leave VLM untouched, and its labels let the detector recover. Under a year-long simulated arms race in which the CAPTCHA operator re-crafts its perturbations each month, the solver recovers every round, and a cheap ~70%-accurate open-weight teacher hardens it as effectively as a perfect oracle. Visual CAPTCHA defenses that assume a failing bot stays failing therefore understate how quickly an adaptive solver returns.

Fake Web3 Accelerator Uses npm Packages to Spread Malware and Hijack AI Agent Traffic

news The Hacker News · 2026-10-19 · ↗ original

A fake Web3 accelerator has been observed pushing information stealers and backdoors to Windows and macOS systems using malicious npm packages under the pretext of offering free artificial intelligence (AI) credits for Anthropic Claude and Google Gemini, coding tools, and security audits.

"The tools delivered information-stealing malware and backdoors for macOS and Windows machines," Elastic Security Labs researchers Jia Yu Chan and Daniel Stepanic said. "The operation also repackaged a legitimate coding agent to send model requests through attacker-controlled services, while its audit tools generated fabricated security findings."

The scheme poses as a Web3 venture capital accelerator named Apex Accelerator to target cryptocurrency startups and founders. It's being tracked under the moniker REF8801. The names of the npm packages, each of which targets both Windows and macOS machines, are listed below -

  • @apexacc/cli (Apex Copilot CLI — AI advisor for Web3 founders) -
  • @apexacc/audit (Web3 Security Scanner — 18 tools for DYOR and smart contract auditing)

While both the packages and their associated GitHub repositories are no longer accessible, "@apexacc/cli" was advertised as an "AI advisor for Web3 founders" that's powered by Claude Fable 5 and Gemini 2.5 Flash.

"@apexacc/audit," on the other hand, claimed to be a Model Context Protocol (MCP) server exposing 18 security tools for scanning tokens, wallets, and smart contracts. Both packages were published by an npm user named "apexaccelerator" and linked to a GitHub account called "apexaccs" and an entity referred to as the Apex Foundation.

It's unclear who is behind the operation, but Elastic Security Labs said it spotted Russian-language comments in the source code commit history. However, these clues alone are not sufficient to definitively establish their identity or origins.

Interestingly, the campaign itself is not new. In late July 2026, SafeDep detailed three other npm packages linked to the same operation that were found distributing a macOS stealer belonging to the Atomic Stealer (aka AMOS) family -

  • @apexfdn/apex
  • @copilot-mcp/apex, which features the same package description as "@apexacc/cli"
  • @apexfdn/copilot-mcp, which claims to be an Apex Copilot and MCP server for "portfolio diligence and operator tools"

Artifacts captured by Socket show that the Apex Foundation has been linked to at least two distinct domains since April 2026

  • apexaccs[.]org
  • apexfdn[.]xyz

According to Internet Archive snapshots dating back to March 19, 2026, the foundation states: "The Apex Foundation offers $235,000 investments, grants, and partnerships, and connects projects with VCs, angels, and private equity if they don't meet our criteria."

Posts shared on X show the accelerator approaching developers of cryptocurrency wallets and market intelligence tools for traders with offers of direct investment and instructions to run their due diligence tool ("@apexacc/cli"). In the case of the latter, the npm package has been found to drop an encrypted malware loader disguised as an Apple app ("com.apple.system.loader").

"The group also sought to build credibility through its presence at TOKEN2049 in Singapore and other in-person events it has hosted in the past," Elastic said. "The group attempts to manufacture legitimacy by appearing at widely attended conferences, indirectly lending credibility to the project."

Once installed, neither of the npm packages provides the promised functionality. The 18 security tools part of the @apexacc/audit package generate fabricated findings, while @apexacc/cli's scoring test returns an unsupported assessment of a fictitious project.

Instead, their primary responsibility is to propagate a macOS backdoor called CloudSyncD and a custom Windows information stealer that exfiltrates data through Telegram. The platform-specific executables are retrieved from the projects' GitHub releases.

Both packages implement a distinct verification path for Windows and macOS by sending an HTTP POST request to "win32" or "darwin" to "vrf.apexaccs[.]org/api/v1/vrf" to initiate the appropriate next stage. The Windows and macOS infection chains are as follows -

Windows -

  • The malware retrieves a Base64-encoded PowerShell command, which reaches out to another endpoint ("0auth-chromium[.]com/APIService") to fetch a second PowerShell script ("drop.ps1") that downloads an executable ("bludness.exe") from "ehegisnightmare[.]icu" and launches it in a hidden window.
  • The PyInstaller executable is a Python loader that checks if it already has administrator privileges and, if so, downloads the next stage from "ehegisnightmare[.]icu," saves it as "%TEMP%\exegis.exe," and launches it. If not, it attempts to bypass User Account Control (UAC) using UACME's ucmDebugObjectMethod().
  • The "exegis.exe" binary is another PyInstaller executable that collects system metadata, running processes, and performs anti-virtual-machine (anti-VM) checks before decrypting and launching a bundled loader as "%TEMP%\updater_loader.exe."
  • The Golang executable patches Antimalware Scan Interface (AMSI) and Event Tracing for Windows (ETW), unhooks "ntdll.dll" to blind endpoint security tools, and loads the next-stage shellcode into its own memory.
  • The shellcode is a native information stealer that examines for signs of a prior infection and then harvests system information, clipboard text, process listings, Wi-Fi profile names, screenshots, and data from wallets, browser extensions, messengers, remote-access and file transfer protocol (FTP) applications, virtual private network (VPN) clients, browsers (Google Chrome, Microsoft Edge, Mozilla Firefox, and Yandex), and game clients. The stealer can also bypass Chrome's app-bound encryption (ABE) protections to extract saved passwords, session cookies, browsing history, download records, and profile metadata. The collected data is exfiltrated through Telegram.

macOS -

  • The malware downloads a remotely hosted bash script and executes it on the machine.
  • The shell script downloads a GZIP-compressed archive from "verify.apexfdn[.]xyz/unix/," saves it as "package.tar.gz" in a temporary directory, and extracts its contents.
  • The archive contains a dropper for CloudSyncD, which first phishes the victim's system login password using a fake authorization prompt and then uses it to launch an embedded payload with sudo privileges. The payload performs host discovery, collects hardware and operating-system details, and then contacts an external server ("ccmihr[.]com") to transmit the data and receive further tasks that allow the malware to download and run additional payloads.

It's worth noting that CloudSyncD was first documented by Jamf Threat Labs late last month, detailing its propagation via a fake Zoom installer. The malware was detected in the wild in mid-September 2026.

"Its behaviors illustrate how macOS malware continues to move toward native implementations, string protection, and execution paths that attempt to avoid writing payloads to disk, while still depending on the oldest technique available: asking the user for their password," Jamf said.

Besides deploying a stealer and backdoor depending upon the infected operating system, the packages are capable of intercepting and redirecting OpenRouter large language model (LLM) traffic, as well as registering an MCP server under their control in the victim's agent configuration.

"These changes allow the attacker-controlled API to receive the prompts, conversation history, code snippets, and tool outputs included in the agent's LLM requests," Elastic researchers explained.

"The attacker's MCP server can also supply instructions that are added to the agent's prompt, along with tool names, descriptions, and accepted inputs that help the model decide which tools to invoke and how to use them. Together, these mechanisms give the attacker visibility into the submitted data and a way to influence the agent's subsequent actions."

MITRE ATT&CK v20 Catalogs AI Abuse, MFA Bypass, Water Utility Attacks

news SecurityWeek · 2026-10-19 · ↗ original

MITRE last week released version 20 of its ATT&CK framework, adding entries that cover AI abuse, MFA bypass, and recent attacks on water utilities.

The organization says the biggest change in ATT&CK v20 is “expanded coverage of recent adversary activity and tradecraft.”

The Enterprise domain gets nine additions, counting both techniques and sub-techniques. Prompt injection is now tracked as two techniques, one for malicious instructions typed straight into an LLM’s interface and one for instructions hidden in material the model ingests.

Another technique describes attackers using an organization’s own AI agents to steal data. Sub-techniques also cover poisoning web content to sway AI search and assistant recommendations, and disrupting LLM-assisted analysis of malware.

Separately, a new technique tracks the theft of application-specific passwords, which attackers can use to sign in without an MFA prompt. Another addresses bypassing CAPTCHA checks, with sub-techniques for automatically solving them and for avoiding them.

The sub-technique for compromised software dependencies and development tools now also covers IDE and coding agent configuration files. MITRE says the additions help capture “how adversaries get around Multi-Factor Authentication, bot checks, and AI systems.”

In ICS, a new campaign tracks attacks on internet-exposed PLCs at more than 30 water and wastewater utilities in Minnesota, which left operators locked out of their systems. Some reports have said the wider wave resembles Iranian-affiliated activity, but MITRE notes that attribution for the Minnesota intrusions “remains unconfirmed.”

A second campaign documents an AI-assisted breach of Mexican government institutions that spanned IT and OT and reached a municipal water utility.

ICS now also includes the Command and Scripting Interpreter Technique, with sub-techniques for six interpreters, replacing the deprecated Command-Line Interface and Scripting techniques. Two other new sub-techniques cover command and control traffic hidden in DNS and publish/subscribe protocols.

On the threat actor front, MITRE added Nimbus Manticore, an IRGC-associated espionage group targeting aerospace, defense, and telecoms organizations, along with its tools. China-backed Salt Typhoon’s entry now covers its exploitation of network edge devices, while the entry for North Korea’s APT38 reflects a shift from financial theft to software supply chain attacks.

Also new is The Gentlemen, a group running a ransomware-as-a-service operation.

Defenders get 15 new detection strategies, six for Enterprise and nine for ICS, backed by 38 analytics. The new ICS analytics are designed to ignore routine engineering and maintenance work.

For Mobile, MITRE brought back a technique for delivering malicious apps outside official stores, last included in v11. It also added NGate, malware that relays payment card data through a phone’s NFC, which allows attackers to withdraw cash from ATMs.

Microsoft: October Windows Server updates break Exchange sign-in, mail flow

news BleepingComputer · 2026-10-19 · ↗ original

Microsoft has confirmed that this month's Windows Server security updates are causing OWA sign-in and mail delivery issues on some Exchange Server systems.

In a new Windows release health dashboard update over the weekend, Microsoft said users may have trouble accessing email or signing in to Outlook after installing the latest updates on systems running Windows Server 2019 and later.

In some cases, affected customers are also reportedly seeing Exchange Server OWA failing with a "MapiExceptionMdbOffline: Unable to make connection to the server. (hr=0x80004005, ec=1142)" error and Event ID 1006 in the application log.

"After installing the October 2026 Windows security update [..], some on-premises Exchange servers might experience issues accessing or sending email. Users might be unable to sign in to Outlook on the web (OWA), or email messages sent from Outlook might remain in the Outbox and not be delivered. Additionally, Exchange might experience issues accessing mailboxes during mailbox replication," it said.

"The October 2026 update introduced a default limit on the amount of memory used by Endpoint Mapper when handling Endpoint Lookup calls. For workloads such as Exchange Server, the default limit of 512 simultaneous Endpoint Lookup calls might not be sufficient under heavy load. Administrators can use this registry setting to increase the maximum number of simultaneous Endpoint Lookup calls, which increases the amount of memory that Endpoint Mapper can use."

However, Microsoft says these known issues aren't linked to the October 2026 Exchange server security updates and urges customers not to uninstall them.

"Issues reported are not related to installation of October 2026 security updates for Exchange Server. This is not a 'known issue' related to October 2026 Exchange update. Any version of Exchange that runs on impacted versions of Windows could be impacted," Microsoft added in a separate blog describing the issues.

"Not all Exchange servers will be impacted by installation of those updates equally; the severity and speed of impact varies based on Exchange server load. Some servers might never see a problem."

While it works on a fix, Microsoft also shared a temporary workaround that should resolve these issues by modifying a registry key on affected Exchange Server systems.

To do that, you have to run the following command from an elevated Command Prompt on the Exchange Server and then reboot the device:

reg add "HKLM\SOFTWARE\Microsoft\Rpc" /v EpmapSavedContextCap /t REG_DWORD /d 65536 /f

After the system restarts, customers should monitor the Exchange environment and raise the Endpoint Mapper memory limit if it reoccurs.

In July. Microsoft also announced that it will stop shipping extended security updates for Exchange 2016 and 2019 this month after a 6-month extension announced in April 2026 to the original Extended Security Update (ESU) program.

Linux KVM guest-host escape rated critical, may represent a new way to attack penguin-powered networking

news The Register · 2026-10-19 · ↗ original

Paulos Yibelo, the researcher who in early October claimed to have found a guest-host escape flaw in Linux KVM, the hypervisor used by most hyperscale clouds, has named the flaw PwnEscape and warned it might represent a new way to attack Linux – on top of being a 9.3-rated critical nasty in its own right. Yibelo’s work is now CVE-2026-99999. It is a scary bug because it makes a guest-host escape possible with a few malformed IPv4 packets. Such attacks are a nightmare security scenario because the whole point of virtualization is carving up hardware into isolated “guest” virtual machines that share a “host” server’s resources – without ever being able to see what other guests or the host are doing. Public clouds rely on that isolation remaining impervious. So do private clouds, because if guest/host isolation is violated, an attacker could conceivably access all the VMs on a host or pool of virtualized hardware. Attacks on a host could give an evildoer access to thousands of VMs, plus containers because many developers now run those constructs in a micro-VM to keep them isolated. PwnEscape makes it possible for guests to access the host, by sending a guest malformed IPv4 packets. As explained in a message from Red Hatter Michael S. Tsirkin in the Linux kernel stable tree, ‘If a packet with bad checksum metadata gets into the ipv4 stack, skb_checksum_help can corrupt the network header and cause a bunch of mischief.” Analysis from threat-finding firm SOC Prime details the mischief. “Linux allows network packets to carry metadata indicating where a checksum operation should begin and where its result should be written. This optimization is legitimate and widely used for checksum offloading, but the security problem arises when less-trusted guest-controlled metadata can influence a write after the packet header has already passed earlier validation stages.” “Because the disclosure could be triggered repeatedly, an attacker controlling a guest workload could potentially collect information from a security domain that the virtual machine should not be able to inspect. This represents a direct failure of the guest-host isolation boundary.” Red Hat’s report says the impact can potentially include “arbitrary code execution on the host, a system crash resulting in Denial of Service, or information disclosure of sensitive memory.” A new class of threat Paulos Yibelo, the researcher who found the flaw, thinks he stumbled upon a novel attack. “As far as we know, PwnEscape exposes an entirely new class of attacks in Linux networking: untrusted checksum metadata can rewrite security-sensitive packet fields after the kernel has already validated and acted on them, undermining assumptions across the networking stack far beyond the original VM escape,” he wrote. “The popular mental model is that VM isolation lives in the virtual-machine monitor. Much of it does. But an attacker-controlled workload does not interact only with arch/x86/kvm/. It interacts with a host OS full of optimized, highly composable interfaces.” “If the metadata crosses a trust boundary, every deferred consumer has to inherit the right invariants. And if the packet can be transformed after those invariants are checked, the invariants have to remain true in the new representation.” “That is why a bug that looks, at first, like a malformed checksum hint can become a memory disclosure and a guest-to-host escape primitive. The problem was not how difficult IPv4 is to parse. It was that different parts of Linux were allowed to trust different versions of the same packet.” That’s an important observation, because while Linux KVM is widely used, and free, it is part of Linux – a project comprised of over 40 million lines of code. A vendor named Edera, which offers a secure container runtime based on the Xen hypervisor, last week none-too-gently pointed out that’s a big attack surface and that researchers have found seven escape bugs this year alone including Januscape. AWS, which runs its cloud on KVM, says its elastic compute cloud is not at risk. Google Cloud’s method of using KVM means it is probably in the clear, too. Developers have created an upstream fix in the Linux kernel. It’s percolating into major distros like Debian, RHEL, and Ubuntu and hopefully into virtualization products that rely on KVM, such as Nutanix and Proxmox. In the age of AI, miscreants will doubtless quickly explore Yibelo’s discoveries, making PwnScape potentially quite a moment for Linux developers and users. ®

The Noise Inside the Network: How an Unsophisticated Attack Exposed a Third-Party Risk

threat-intel Unit 42 · 2026-10-13 · ↗ original

When unusual activity was detected on a European bank’s central IT system, its internal security team quickly recognized that the incident warranted immediate response. They discovered unauthorized VPN-based access attempts that spanned several months. They then engaged Unit 42 to determine the full scope of the intrusion, identify any persistent footholds and secure the environment.

While the activity appeared to be a stealthy cyberespionage campaign, the actual intrusion was made possible by gaps in foundational security controls. Rather than relying on novel techniques, the threat actor succeeded through persistence, exploiting weaknesses that stronger identity protections and basic security hygiene could have prevented. The case highlights an important lesson: Sometimes the most damaging intrusions begin with the simplest oversights.

Internal Reconnaissance: A High-Volume, Noisy Campaign

The intrusion originated through a third-party-managed external gateway appliance that was not properly configured to enforce strict authentication. Using compromised credentials, the attacker began by authenticating to internal systems. Once inside, the threat actor launched a discovery campaign of the internal network.

The threat actor conducted multiple rounds of reconnaissance, performing extensive host and network scans across a wide range of protocols and interacting with thousands of systems. This broad, noisy approach was less a targeted strike than casting a net to uncover as many access points as possible.

Authentication Abuse and Documentation Browsing

The pattern continued with credential testing. Over a period of a few months, the threat actor launched multiple password-guessing campaigns. They hammered at internal systems with brute-force authentication attempts, focusing on administrator accounts.

While doing this, they systematically targeted internal documentation and data shares. Using automated web requests, they scraped individual pages and attachments from internal systems and enumerated various operational and network shares.

The activity observed did not match the behavior typically associated with a sophisticated threat actor. The noise behind the scanning and login attempts, along with using common system identifiers, pointed to an opportunistic attacker attempting to compromise multiple systems. Their actions showed little effort to remain hidden or avoid detection.

Early Detection, Containment, and Remediation

What This Investigation Revealed

This case serves as a critical reminder that not every cyber threat is advanced and multifaceted.   • Using endpoint detection to stop lateral movement
